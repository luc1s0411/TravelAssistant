# 旅行助手 H5

以旅行助手为主入口：收集出行预算与偏好，引导用户到住宿、美食、景点窗口选择项目，确认后生成带时间线和地图的旅行规划，并支持自然语言查询和修改。

> 当前状态：仅有需求与协作说明，尚未实现业务代码。  
> 团队：4 人，1 人负责需求与代码评测，3 人负责业务开发。  
> 日期：2026-11-04。本文按项目 README 编写，对应本次所说的“remark 说明书”。  
> 产品需求与验收：[需求说明书](需求说明书.md)。以下目录、启动命令及接口均为待实现约定，当前不能当作已存在的运行环境。

## 1. 本版范围

核心流程：**助手问需求 → 确认预算口径 → 分类窗口选择 → 确认本次资料 → 生成规划 → 我的规划查看流程与地图 → 查询和修改。**

- 主入口为旅行助手，三个选择窗口共享同一规划草稿。
- 只保存用户选中的项目、必要输入和生成计划，不批量复制平台商家资料。
- 高德用于地点、路线和地图，和风用于天气辅助。
- 携程及其他商品资料仅在获得对应权限后接入，不把参考消费当实时报价。
- 本版不做付款、跳转预订、退款、订单同步或手动支付状态。
- 个人草稿和计划由后端保存，并按用户隔离；正式环境不能使用共享演示用户代替认证。

仓库中若同时保留此前的《旅游助手需求分析》《旅游助手 API 与实现方案》《旅游助手新方案可行性分析》，它们仅作历史参考；以本 README 和配套需求说明书的当前版本为准。历史文件不应作为本轮业务开发任务清单。

## 6. 跨模块接口约定

完整清单在需求说明书第 8 节；公共基础阶段将详细样例补到 `docs/contracts.md`，三人评审后冻结。

| 调用方 → 提供方 | 必须事先一致的内容 |
| --- | --- |
| A → B | 登录与身份、草稿读写、候选筛选、加入和移除、价格与来源格式 |
| A → C | 助手响应、确认输入、生成、完整／条件查询、修改预览及确认 |
| C → B | 当前用户校验、草稿与选择读取、草稿版本、地点、路线、天气 |
| B／C → A | 统一错误、空结果、计划状态、地图数据、版本冲突和失败可重试性 |

共同规则：

1. 所有业务路径加 `/api/v1`，JSON 使用 `snake_case`，ID 为字符串，日期为 `YYYY-MM-DD`。
2. 金额为整数分，币种单列；住宿、美食、景点预算使用约定单位。`null`、不限、0 分必须区分。
3. 经纬度明确命名并记录坐标类型；后端统一不同来源，前端不自行猜转换。
4. 返回 `code`、`message`、`data`、`request_id`；HTTP 状态和业务错误一致。
5. 客户端不得靠提交 `user_id` 决定资源归属，后端根据可信登录身份过滤所有读取和写入。
6. 草稿用 `revision`；计划用 `version`。确认生成对应精确草稿版本，过时确认须拒绝。
7. 加入候选、生成和确认修改都要处理重复请求；请求重试不产生重复结果。
8. 助手只提出需求更新、候选和修改建议，用户确认后经业务接口落地；模型不直接改库。
9. 普通接口第一版统一返回 JSON；流式进度属于后续可选能力，如启用必须单独定义事件和断线行为。

### 一个必须共同走通的例子

用户提出“两人去杭州三天，住一间房两晚，住宿每房晚 500 元内，美食每人每天 100 元，景点每人本次 300 元”。

- C 解析并返回明确预算单位及待确认项，A 展示确认，B 保存同一草稿。
- A 带 `draft_id` 进入三个窗口；B 按当前已确认条件提供候选。
- 用户加入酒店、餐厅和景点，B 保存选择，A 回到助手显示选择摘要。
- 用户确认本次使用哪些项目，C 校验确认版本并生成计划。
- 住宿预算上限为 `500 × 1 间 × 2 晚 = 1000 元`；美食上限为 `100 × 2 人 × 3 天 = 600 元`；景点上限为 `300 × 2 人 = 600 元`。这些是分类预算上限，不是实际花费或供应商报价。
- A 展示时间线与地图；用户问“第二天住哪里”，C 读取计划对应住宿，不靠模型编造。
- 用户修改第二天午餐，先展示变更及影响，确认后产生新版本。

所有固定数据仅用于联调，不代表这些地点、价格或路线已由真实接口验证。

## 9. GitHub 协作与提交规则

你负责自行创建／上传仓库并管理成员权限，本次没有执行发布。

1. 先上传本 README 与需求说明书，团队评审范围；公共基础走独立小变更。

3. 在自己的分支开发，检查文件和差异后 Commit（提交到本地）。

5. 需求负责人或指定审核人审查；问题修复并复测后，再 Merge（合并）到 `main`。
6. 其他成员更新 `main` 并同步到自己的分支，继续下一个小任务。

`main` 保持可运行。不要直接覆盖队友文件，不把旧项目 `.git` 目录复制到团队仓库。接口字段变更要同步文档、前端类型、测试样例及依赖调用方，不能只改一方。
